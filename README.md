# Video Downloader

## 项目目的

做一个面向个人使用的视频下载器和本地视频库。它支持网页视频和本地可管理的文件下载，并为 BT 资源提供与普通下载不同的文件选择流程。

## 第一阶段边界

- 网页视频由 `yt-dlp` 下载，直链、迅雷链接和 BT 资源由 `aria2` 下载。
- 网页视频保留 `yt-dlp` 已支持的链接、格式、字幕、封面、章节、播放列表和频道等能力。
- `.torrent` 文件会先展示文件列表；磁力链接在获取到元数据后也会展示文件列表，用户可只选择需要的文件再开始下载。
- 磁力链接是否能获得文件列表或开始下载，取决于 DHT 和可用节点；持续无法获得数据的任务会停止并提示重试。
- 下载源实际没有返回的字段（例如封面、上传者、发布日期或章节）不虚构展示。

## 个人视频库

已完成下载的视频保存并展示 `yt-dlp` 返回的数据，例如：

- 标题、缩略图、上传者或频道、原始链接。
- 下载日期、发布日期、时长、分辨率、文件大小和本地路径。
- 播放列表或频道归属、字幕、章节及可用格式。

视频库基于这些字段提供搜索、排序、筛选、观看进度、按播放列表归档，以及下载归档以避免同一来源重复下载。它也支持本地媒体目录扫描、失效路径重新定位、VTT/SRT 字幕、轻量元数据编辑和精确内容重复检测。

以下能力暂不纳入个人工具范围：自定义标签、时间点笔记、AI 识别或转写、云同步和移动端同步。

## 当前技术路线

```text
React 前端
  ↓ HTTP / SSE（仅本机）
FastAPI
  ↓
yt-dlp Python API + ffmpeg
  / aria2
  ↓
SQLite
```

- FastAPI 只监听 `127.0.0.1`，不提供局域网或公网服务。
- 网页视频的下载元数据和进度通过 `yt-dlp` Python API 获得，不解析普通命令行日志；BT 的进度、断点续传和文件选择由 `aria2` 提供。
- SQLite 保存下载任务、文件路径、经筛选的结构化元数据和引擎版本。
- API 从一开始使用 `/api/v1/...` 前缀，前端不直接依赖 Python 模块或 `yt-dlp` 命令。

建议的最小 API：

- `POST /api/v1/downloads/inspect`：解析链接并返回媒体和格式信息。
- `POST /api/v1/downloads`：创建下载任务。
- `GET /api/v1/downloads`：读取任务和下载历史。
- `GET /api/v1/downloads/{id}`：读取单个任务的完整状态。
- `GET /api/v1/downloads/{id}/logs`：读取该任务的下载日志。
- `GET /api/v1/events`：推送下载进度。
- `GET /api/v1/videos`：检索和筛选本地视频库。

## 当前工作台

- **任务管理**：表格优先展示状态、精确百分比、格式和创建时间；点击一行才展开下载详情和日志，避免任务列表被信息淹没。
- **新建下载**：固定在右上角；单个链接可解析格式，多行链接会逐条解析并批量创建任务，打开弹窗时会尝试读取剪贴板中的下载链接。
- **视频管理**：已完成视频独立为表格，可播放、打开目录、复制路径，并可只修改显示标题或同步重命名本地文件及同名附属文件。
- **本机提示**：可选在下载完成或失败时发送 macOS 系统通知；失败任务可复制引擎、输入类型、错误和最近日志。
- **清理维护**：可预览并清理指定天数前的下载日志和终止任务记录；未完成文件和内容完全相同的重复媒体需勾选确认后才会移入废纸篓，每组重复媒体至少保留一份。
- **数据备份**：可导出 SQLite 中的任务、媒体记录、合集和设置；恢复前必须预览并确认，备份不复制媒体文件。
- **版本检查**：可检查 PyPI 上的最新 `yt-dlp` 版本，只给出提示，不自动安装或替换依赖。
- **本地数据库**：使用 SQLite 保存任务、进度、日志和视频记录；数据库默认位于 `data/video-downloader.sqlite3`，无需单独启动数据库服务。

## 桌面应用边界

当前提供原生 macOS 启动器，不实现安装包、多平台分发或自动更新：

- 每条下载记录保存引擎、引擎版本、筛选后的元数据和原始链接。
- 下载只能从后端下载服务启动；界面不直接执行命令。
- 原生启动器负责启动 FastAPI 本地服务并打开 WebKit 窗口；关闭最后一个窗口时停止它启动的后端。
- 如未来新增其他下载引擎，可新增不同 `engine` 值；本地视频库和 API 契约保持不变。

## 当前最小成功标准

用户能提交网页视频、直链、迅雷链接或 BT 资源；网页视频可选择格式，BT 文件列表可选择所需文件，下载任务可被跟踪；下载完成后，视频会进入可检索的本地视频库。

## 本地启动

日常使用可先构建 macOS 桌面应用：

```bash
make macos-app
```

构建结果位于 `dist/Video Downloader.app`，之后可直接双击启动。桌面应用使用当前项目的 `backend/.venv` 和构建后的前端，关闭最后一个应用窗口时会安全停止由它启动的本地后端。启动日志位于 `~/Library/Logs/Video Downloader/backend.log`。移动项目目录后需要重新执行一次 `make macos-app`。

开发时仍可在两个终端中启动：

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/uvicorn app.main:app --reload
```

```bash
cd frontend
npm install
npm run dev
```

前端开发服务器默认打开 `http://127.0.0.1:5173`，并将 `/api` 和 `/health` 请求代理到 FastAPI 的 `http://127.0.0.1:8000`。

## 测试与覆盖率

安装后端依赖时会同时安装 `coverage.py` 和 Hypothesis。常用检查：

```bash
make test
make test-fuzz
make test-coverage
```

`make test-fuzz` 使用固定、可重复的 Hypothesis 输入，重点检查链接路由、迅雷解码、torrent/bencode 解析、目录格式、媒体标题和直链文件名安全边界。

`make test-coverage` 会先运行完整后端测试，再执行关键代码覆盖率门禁。关键代码范围由 `backend/scripts/check_critical_coverage.py` 明确维护，包括下载输入与 torrent 解析、aria2 与 qBittorrent 适配器、下载引擎任务执行链、SQLite 初始化与恢复、事件总线，以及文件安全、清理维护、版本检查和媒体重命名；每组行覆盖率不得低于 98%。命令最后仍会输出整个后端的覆盖率，避免把关键代码指标误认为全项目指标。
